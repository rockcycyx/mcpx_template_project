# 2026-10-24 工作日志

## SECS/GEM 多实例架构改造（首轮落地）

### 目标
把通讯层（已按 deviceKey 管多引擎）与数据层（原全局单实例）打通，引入「SECS 实例」一级概念，贯穿数据层/配置层/通讯层/UI 层。

### 决策（用户确认）
- `SecsReport/Ceid` 里的 `device_id` 是指「SECS 实例」ID，且 `SecsVid` 此前**根本没有**实例维度 → 统一收敛为 `instance_id`。
- `SecsVid` 的 `device_code`（PLC 软元件代号）+ `plc_address`（点位）缺「哪台 PLC」归属 → 由 `instance_id → comm_setting_id` 间接携带，VID 不重复挂 comm_setting_id。
- 配置从 appsettings.json 的 SecsGem 单例迁到 `secs_instance` 表（数据表驱动）。
- 路由层上下文注入采用 AsyncLocal（不改 Controller 方法签名）。
- 外键模型：`comm_setting ←(可空 comm_setting_id)— secs_instance ←(instance_id)— secs_vid/secs_report/secs_ceid`。

### 改动清单
1. 新增实体 `SecsInstance`（表 secs_instance：Name/IpAddress/Port/DeviceId/ConnectMode/T3-T8/CommSettingId?/Status）。
2. `SecsVid/SecsReport/SecsCeid` 加 `InstanceId`（required）；`SecsReport/SecsCeid` **删除**孤儿 `DeviceId`。
3. `EFDbContext`：加 `SecsInstances` DbSet；实例↔CommSetting 关系 `HasOne<CommSetting>().HasForeignKey(CommSettingId).OnDelete(SetNull)`。
4. 新增 `ISecsInstanceService/SecsInstanceServiceImpl`（CRUD + QueryEnabledAsync；唯一约束 ip+port）。
5. `SecsGemConfigStore` 加静态 `ToConfiguration(SecsInstance)`（供通讯层从实例实体构造配置）。
6. 三个 Secs 业务 Service 接口 + Impl 全部方法加 `instanceId` 参数；唯一约束改「同实例内编号唯一」；`QueryVidsAsync/QueryReportsAsync` 按实例过滤。
7. 通讯层：新增 `ISecsContext/SecsContext`（AsyncLocal<long?>）；`ISecsGemCommunicationService` 加 `InstanceId` 属性；`SecsGemCommunicationService` 构造注入 ISecsContext，分发前 `SetInstance` 包住 DispatchAsync；`SecsGemManager.StartAsync` 把 deviceKey 解析为 instanceId 写入引擎；`SecsGemAutoStartService` 改为遍历 `QueryEnabledAsync` 逐个启动。
8. VM 层：三个 Tab VM 加 `InstanceId` 属性；FieldViewModel 删 DeviceId 改 InstanceId；`PageSecsConfigViewModel` 加 `Instances`/`SelectedInstance`/`RefreshInstancesCommand`，切换实例重载三 Tab + 树。
9. View：`PageSecsConfig.xaml` 顶部加实例选择器（ComboBox + 刷新按钮），主体套一层 Grid；`SecsReportFieldWindow/SecsCeidFieldWindow` 删「设备 ID」行。

## 旧库迁移（已执行完成）

### 数据库
`mcpx_template_project/bin/Debug/net8.0-windows10.0.18362.0/heron-wtrs.db`（SQLite，连接串 Data Source=|DataDirectory|\heron-wtrs.db）。
已备份为 `heron-wtrs.db.bak_20261024`。

### 实际旧结构（迁移前）
- `secs_instance` 已存在，含 1 条数据但 **id=0**（主键从 0 开始，异常）。
- `secs_vid`：**缺 instance_id**，多 `unit` 列（新实体无此属性），4 条数据。
- `secs_report` / `secs_ceid`：有 `device_id`（值=0），**缺 instance_id**，各 1 条。
- 关联表 `secs_report_vid`(3条) / `secs_ceid_report`(1条) 正常。

### 迁移动作
1. 三表 `ALTER TABLE ADD COLUMN instance_id INTEGER NOT NULL DEFAULT 0`。
2. 重建表删 `secs_report`/`secs_ceid` 的 `device_id` 列、删 `secs_vid` 的 `unit` 列。
3. 恢复三表 `id INTEGER PRIMARY KEY AUTOINCREMENT`（`CREATE TABLE AS SELECT` 会丢主键自增，已用 rename 重建修复）+ 同步 sqlite_sequence 序号。
4. 修正 `secs_instance.id` 0→1，并同步三表 instance_id 0→1（避免 EF 将 id=0 误判为「未持久化」）。

### 迁移后
- 三表结构与实体完全对齐：instance_id 均有值=1，指向唯一实例 id=1。
- 数据完整：secs_vid 4 条、secs_report 1 条、secs_ceid 1 条。
