## PLC 握手协议重构：成功位 → 回复位三态 + PlcHelper 封装

用户明确 PLC 交接协议为三态握手，并指出 IsOn 等工具方法应下沉到 PlcHelper。

### 1. 回复位三态协议（替换原"触发位+成功位"）
- 回复位值：0=无回应(指令处理中)、1=ACK、2=NAK。
- 流程：逐字段写值 → 触发位置1 → 轮询回复位 → 触发位复归0 → 回复位复归0。
- `PlcWriteRole.Success` → `Reply`；`PlcObjectPlan.Success` → `Reply`。
- `Recipe.WriteSuccess(bool)` → `WriteReply(int)`，注解 Role=Reply，地址仍 M2101。

### 2. 新建 PlcHelper 静态工具类（Service.Business.Plc）
- `IsOn`、`ReadCachedValue` 从 PlcObjectService 下沉。
- 新增 `ParseReply`（三态解析）与常量 `ReplyPending/ReplyAck/ReplyNak`。

### 3. PlcObjectService 重写 WriteAsync
- 三态握手流程，WaitForReplyAsync 轮询回复位（超时5s）。
- IsWriteSuccess 改为读回复位判 ACK。

### 4. Mock 三态模拟
- SimulateRecipeWriteAsync：写值回写读点 → 回复位置ACK(1) → 等触发位复归0 → 回复位复归0。

### 遗留疑点（待用户确认）
- 回复位 M2101 是 M（位）设备，但三态需存 0/1/2（含 NAK=2），位设备只能 0/1。是否应改为字设备（如 D）？当前按原地址 M2101 实现，NAK=2 场景无法在真实位设备表达。已 flag 给用户。
- 用户答复：该点位（M2101 回复位）暂且跳过，不改。
