## PageDashboard 机台状态数组越界修复
- 现象：System.IndexOutOfRangeException at `stateCount[(int)state]++`（生产看板页 2s 刷新时）。
- 根因：`PlcValueConverter.Convert(text, enumType)` 对枚举走 `Enum.Parse`，数值字符串如 "3"、"-1" 会**成功**转成未定义枚举值（不抛异常），`(int)` 后做数组下标即越界。
- 修复（PageDashboardViewModel.RefreshRealtimeCharts）：
  - 改用 `ToInt(current, "MachineState")` 取原始整数，`stateValue is >= 0 and <= 2` 判定；缺失/非法返回 -1。
  - stateCount 扩为 4 桶，越界值归入「未知」（#90A4AE），不再静默丢弃机台。
  - 顺带修正：平均有效功率按「已连接机台数」取平均（原来除总机台数）。
- 教训：PLC 缓存值转枚举必须校验数值范围，禁止直接拿枚举值当数组下标。
- dotnet build 通过 0 错误。

## MainWindow 侧边栏菜单搜索失效修复
- 现象：AutoSuggestBox 输入关键字后侧边栏菜单无任何过滤反应。
- 根因：iNKORE.UI.WPF.Modern 0.10.2.1 的 `AutoSuggestBox.TextProperty` 用普通 `PropertyMetadata` 注册（非 FrameworkPropertyMetadata，`BindsTwoWayByDefault=false`），XAML 里未写 `Mode=TwoWay` 时绑定为 OneWay → 输入只更新控件自身 Text，永不回写 VM.SearchText，`OnSearchTextChanged` 不触发。
- 用反射验证：`AutoSuggestBox.TextProperty.GetMetadata(...)` 的 metaType 为 `PropertyMetadata`。
- 修复：
  - MainWindow.xaml：`Text="{Binding SearchText, Mode=TwoWay, UpdateSourceTrigger=PropertyChanged}"`。
  - MainWindow.xaml.cs：`BuildNavigationItem(menu, expandAll)` 增加 `IsExpanded = expandAll && menu.IsExpanded`，搜索时自动展开命中父级链。
  - 顺手删掉 MainWindowViewModel 重复的 `using iNKORE.UI.WPF.Modern.Controls`（CS0105）。
- 经验：iNKORE/ModernWpf 控件里凡 DP 未显式声明 TwoWay 的，绑定一律要写 `Mode=TwoWay`，否则静默单向失效（TextBox.Text 才默认双向）。

## 搜索二次修复：MenuItems.Clear() 抛 ArgumentOutOfRangeException
- 现象：双向绑定生效后，一输入就在 `NavigationViewRoot.MenuItems.Clear()` 抛 ArgumentOutOfRangeException，绑定层报「Cannot save value from target back to source」，搜索又静默失效。
- 根因：搜索时逐键 `MenuItems.Clear()` + 重建整棵菜单项。Clear 发生在绑定「目标→源」回写链路内，且当时存在选中项，iNKORE NavigationView 内部会按下标取已移除的项 → 越界；异常冲掉本次绑定回写，SearchText 停在旧值。
- 修复（关键设计：搜索不再动集合）：
  - ViewModel：`MenuStructureVersion` 只在结构变更（登录/登出/菜单变更）时自增；`OnSearchTextChanged` 只 `MenusRebuilt?.Invoke()`，不再重建菜单树；删除 `FilterMenus(keyword)`/`CloneForNav`（过滤改由 View 处理）。
  - MainWindow：`RefreshNavigation()` = 版本变化才重建 + 每次 `ApplyMenuFilter(SearchText)`；`ApplyMenuFilter` 递归切 `NavigationViewItem.Visibility` 并展开命中父级链，父级名命中则整棵子树放行；`RebuildNavigationMenu` 在 `Clear()` 前先 `SelectedItem = null`。
- 教训（WPF/iNKORE）：绝不要在绑定回写或 TextChanged 同步链路里 Clear/Mutate ItemsControl 的 ItemsSource；同类过滤场景优先用 Visibility 过滤，别重建集合。
- dotnet build 通过 0 错误。
