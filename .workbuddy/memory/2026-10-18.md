## 修复：停止监听卡死 + COMACK 解析错误

### COMACK 解析
- S1F14 实际格式 `L[2] { B[1] COMMACK, L[0] MDLN }`，COMMACK 是**第一个**子项（`Items[0]`），之前误用 `Items[^1]` 取到空 List 导致 commack=255 一直重试。

### 停止监听卡死根因
- `StopInternal` 在持有 `_lock` 时同步 `DisposeAsync().AsTask().GetAwaiter().GetResult()` 阻塞等待，与 secs4net 内部连接线程/消息循环形成死锁。
- 修复：`Stop()` 锁内只做「取消 token + 置空引用 + 更新状态」的快速操作，把 `DisposeAsync`/`Dispose` 移到锁外后台异步执行（`ReleaseAsync`），绝不阻塞 UI 线程。
- 新增 `_releaseTask` 字段追踪异步释放；`Start()` 在重建连接前 `GetAwaiter().GetResult()` 等待旧释放完成，避免端口 `AddressAlreadyInUse`。

## 追加任务：SVID/DVID/Report 注解 + 多设备引擎（每设备一个 Secs 实例）

### 背景
用户需求：用注解在类/属性上标记 SVID/DVID/Report，未标注属性排除；EQP 端对多设备，用「每设备一个 Secs 实例」方案区分。

### 关键结论（已核实 secs4net 3.1.0 源码）
- `HsmsConnection` 是**单连接模型**：内部单个 `Socket _socket`，Passive 模式 `AcceptAsync` 一次后退出循环，**不支持同一端口并发多 Host**。
- HSMS 头 `MessageHeader` 里**没有暴露 SessionId**：`DeviceId` 解析用 `& 0b01111111_11111111` 把 SessionId 位（bit15）剥掉了，上层拿不到。
- 区分「哪个设备」的标准字段是 **DeviceId**（bit0~14），不是 SessionId（SessionId 区分同设备主从会话，secs4net 内部已处理）。
- 结论：多设备用「每设备一个端口 + 一个引擎实例」隔离，无需解析 SessionId/DeviceId（连接本身已隔离）。

### 新增文件（`Controller/SecsGem/`）
- `SecsVideoAttributes.cs` — `SvidAttribute`（属性级，状态变量只读）+ `DvidAttribute`（属性级，数据变量可读写）+ `ReportAttribute`（类级，Report 组）。
- `SecsVideoModel.cs` — `VideoKind` 枚举 + `VideoEntry`（VID→属性映射）+ `ReportGroup`（ReportId→VID 集合）。
- `SecsVideoRegistry.cs` — 反射扫描器：`Scan(Assembly)` 收集带 [Report] 或含 [Svid]/[Dvid] 属性的类型；产出 `Svids`/`Dvids`/`Reports` 索引；VID 编号冲突告警；未标注 VID 属性自动排除。
- `ISecsGemManager.cs` + `SecsGemManager.cs` — 多设备管理器：`Dictionary<deviceKey, ISecsGemCommunicationService>`，每个设备一个引擎实例，启停/路由/主动发送。
