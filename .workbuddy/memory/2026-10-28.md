## 补充：值来源切换导致控件渲染异常的根因

- 现象：切换「值来源」(db↔plc) 后，注解字段/设备代号/点位地址三控件显示异常。
- 根因：三控件用了**显式 Style + DataTrigger** 控制 Visibility，显式 Style 覆盖 inkore 主题隐式样式，导致切换显示后控件退回 WPF 默认灰白外观（丢失 Fluent 样式）。
- 修复：移除显式 Style，改为控件 `Visibility` 直接绑定 `IsPlcSource`（VM 已有布尔属性，OnSourceChanged 里已通知）+ `BooleanToVisibilityConverter`。
- 经验：WPF 中给控件挂显式 Style 会覆盖 inkore 的隐式主题样式；要叠加触发器需 BasedOn 主题样式，或改用直接属性绑定 + 转换器。

## S2F23 → S6F1 Trace 采样上报功能实现

- 需求：Host 下发 S2F23（定义 Trace）后，设备端按 DSPER 周期采集 SVID 值并主动上报 S6F1。
- 架构链路：S2Controller.S2F23 → IS2EquipmentService.InitializeTraceAsync → IS2TraceService.InitializeAsync → SecsTraceService（内存维护 Trace 定义 + 后台 Timer 采样）→ ISecsGemManager.SendAsync(deviceKey=instanceId.ToString(), S6F1)。
- S6F1 报文结构：L,4 [TRID U4, SMPLN U4, STIME A(YYMMDDHHMMSS), L,n [SV...]]（replyExpected=false）。
- 新增文件：
  - Service/Business/Secs/IS2TraceService.cs（接口）
  - Service/Business/Secs/impl/SecsTraceService.cs（实现：每个 Trace 独立 System.Threading.Timer，TOTSMP=0 禁用/删除，TOTSMP>0 达到上限自动停用）
- 修改文件：
  - S2EquipmentService.cs：注入 IS2TraceService，InitializeTraceAsync 委托落地（删除旧的 IsValidDsper 静态方法）
  - BusinessServiceRegister.cs：注册 IS2TraceService → SecsTraceService（单例）
- DSPER 解析：hhmmss(6)/hhmmsscc(8，厘秒)/hhmmsszzz(9，毫秒) → 毫秒周期。
- SVID 值读取复用 ISecsValueReader.ReadAsync + ISecsVidService.QueryAllAsync(instanceId, SVID)。
- 编译：CS/MC/XLS 编译错误=0（MSB 错误是 exe 被运行中进程 PID 锁定，非代码问题）。

## 修正：S6F1 回报时机与报文结构（REPGSZ 打包）

- 原实现错误：S6F1 每包只含 1 个样本，且报文结构误用 L,4 [TRID, SMPLN, STIME, SV]，忽略了 S2F23 的 REPGSZ（Items[3]）。
- 正确语义（SEMI E5）：
  - 单个样本采样间隔 = DSPER；S6F1 上报间隔 = DSPER × REPGSZ；总采样时长 = DSPER × TOTSMP。
  - 每包 S6F1 内样本数 = REPGSZ；每个样本内数据条数 = SVID 列表长度。
  - SMPLN 从 1 连续递增到 TOTSMP，达到后自动停用。
- S6F1 正确报文结构：L,2 [DATAID(=TRID) U4, L,n [L,3 [SMPLN U4, STIME A, L,m [SV...]]...]]。
- 改动：S2Controller.S2F23 解析 REPGSZ 并透传；IS2EquipmentService.InitializeTraceAsync 增 repgsz 参数；IS2TraceService.InitializeAsync 增 repgsz；SecsTraceService 重写为「按 DSPER 采集→缓冲→攒够 REPGSZ 打包上报→TOTSMP 达上限 flush 剩余样本并停用」。
- 编译：CS/MC/XLS 错误=0，完整通过。
