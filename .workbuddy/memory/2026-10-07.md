## PLC 通讯架构重构设计（方案阶段，尚未写代码）

- 用户引用《D:\Docs\C#\通讯架构.md》（配置优先、注解兜底四层点位方案），要求迭代现有 PLC 通讯架构。
- 关键诊断（用户主动指出，判断正确）：
  1. `PointValueVO.Quantity` 表示「一段连续地址」，一个 PointValueVO 对应一段区域，与「一个业务属性」粒度错位。
  2. `LocalPosition` 字段设计不合理、类型无约束、业务零使用，应删除。
- 方案结论：通讯采集层（按段批量读，不动）与业务点位层（按属性精确访问，新增）解耦。
  - 新增 `plc_point` 表：object_type + property_name + data_type + device_code + address + offset + writable。
  - offset 让业务属性精确绑定「某段地址第 N 个值」，现场改表即改点位、免重编译。
  - 注解兜底 + 数据表优先；表达式树编译读写委托；`IPlcRepository` 面向对象门面。
- 产出文档：
  - `D:\Docs\C#\通讯架构-重构设计.md`（正式方案，待评审后落地代码）
  - `D:\Docs\C#\通讯架构-迭代设计.md`（已标记作废，被重构设计取代）
- 关键修正（用户指出注解在多 PLC 场景失效）：注解只能写死一个地址，多台机同属性不同地址时注解失效。定位必须引入机台维度 `machine_id + object_type + property_name`，`plc_point` 表加 `machine_id` 字段，唯一键改为三维，每台各配一条记录，注解仅作单机兜底 + 类型声明。
- 最终定案（用户进一步澄清）：**继承为主 + 表覆盖为辅**。不同机台型号 = 不同子类 = 不同 `[PlcPoint]` 注解（强类型、编译期检查、开闭原则）。`plc_point` 表降级为可选覆盖能力（现场微调用），默认不依赖。现场改点位可接受重编译，热重载非硬需求。
